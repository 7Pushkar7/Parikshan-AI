        How Parikshan works

        An LLM turns text into text. An agent is an LLM running inside a loop, with tools it can call and memory it can read. Parikshan is the second kind.

        LLM call

        One HTTP request to the model API. You send the model name, messages and settings. You get back text plus a token count. No tools, no memory unless you resend the chat.

        Tokens and cost

        Billing is per token (about ¾ of a word). Input is everything you send, including history and tool results. Output is what the model writes, including thinking, and costs about 5× more. Agents use many input tokens because every step resends the history.

        Tools

        Python functions with a name, description and argument schema. Gemini reads the descriptions and replies "call search_pubmed with these arguments". Our code runs it and sends the result back.

        LangGraph

        The agent framework. The loop is a small graph: an agent node, a tools node and an edge that checks whether Gemini asked for tools. It handles streaming, step limits and memory.

        Memory

        Conversation: saved to SQLite after every step, per thread, so follow-ups work. Evidence: fetched papers and trials go into ChromaDB. Logs: runs, tokens and costs go to a second SQLite file.

        RAG

        Before writing a report, the agent searches ChromaDB for the most relevant evidence and gives only that to Gemini, which must cite it. Citations to anything never fetched are flagged.

        FastAPI

        The Python web server. It turns functions into URLs like POST /api/chat/stream, validates input, streams each agent step live, and serves this page. Docs at /docs.

        Backup model

        If the main Gemini model is overloaded (503) or rate-limited (429), every call switches automatically to a lighter backup model so the run still finishes.
